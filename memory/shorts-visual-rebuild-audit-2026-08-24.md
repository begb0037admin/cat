## Confirmed technique: partial-alpha-pixel percentage is a fast, objective matte-quality check

`PIL: Image.open(f).split()[-1].histogram()` → sum everything except bucket 0 (fully transparent) and bucket 255 (fully opaque) = the count of "soft edge" pixels. Divide by total pixels.

- Proven podcast master (`hope-cutout-transparent.png`, `02_Templates/Episode_Square/episode-square/layers/presenter/`): **1.27% partial alpha** — genuine soft/anti-aliased edge. This is what "clean" looks like numerically.
- All three rejected Shorts Hope-figure assets (both `02-hope-investigate-full-figure-transparent*.png` variants, plus all five `hope-expression-library/*.png` cards): **0.00% partial alpha** — a hard binary mask, every pixel fully transparent or fully opaque, zero feathered transition. This is the direct, measurable cause of the visible cyan/blue halo/fringe and jagged hair edges Kevin flagged by eye — not a vague quality complaint, a specific technical defect with a specific number.

Companion check: compositing the RGBA file onto solid black *and* solid white backgrounds (`Image.alpha_composite`) and actually looking at both reveals fringe/halo that doesn't show on a transparent-checkerboard viewer. One asset in this same rejected kit (`04-self-improvement-loop-full-transparent.png`, a glow-effect diagram, not a Hope figure) looked fine on black but showed a clear white halo ring on a white composite — confirms the review process's own "test on light AND dark" requirement is load-bearing, not boilerplate; a dark-only check would have missed this one.

Do this composite-and-measure check on any transparent asset before trusting a prior "Pass" — this session found and corrected two files (`artwork/ALPHA_VALIDATION.md`, `artwork/REVIEW_RECORD.md` under `04_YouTube_Channel/shorts/EP01_Short01_This_Changes_Everything/`) that had recorded "Pass" for the same 0.00%-partial-alpha asset. Their check only confirmed the alpha channel *had* a 0–255 range somewhere in the file (trivially true for almost any RGBA cutout) — it never measured edge softness or checked for holes. A "Pass" in this repo's own QA docs is not itself evidence of quality; re-verify against the actual pixels.
