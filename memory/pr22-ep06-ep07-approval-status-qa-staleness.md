Two small, unrelated cleanup follow-ups, both Kevin-approved, combined into one PR per the task's own instruction. Result: **PR https://github.com/begb0037admin/ai-news-channel/pull/22** (branch `cat/ep06-ep07-seed-approval-and-qa-staleness` off `main`), open, not yet merged.

**Fix 1 — Episode Seed "Approval status" lines.** PR #21 (merged) filled in real Content Briefs for `EP06_G-Zero_Control` and `EP07_AI_Empires`, and each brief's own header now reads "Approved by Kevin, 7 August 2026." PR #21's own body flagged, as a deliberate follow-up, that each Episode Seed's "Approval status" line still said `draft — awaiting both (1) Hope's review of this proposed episode split... and (2) Content Brief approval`. Updated both lines to record the Content Brief approval (date, `PRODUCTION_PROCESS.md` step 3, pointer to the approved brief) — but did **not** mark the whole line "approved," since the split-review half of the original two-part gate is a distinct, separate item (Hope's editorial sign-off on the split itself, as opposed to the content) that this task never asked about and no doc confirms as resolved. Judgment call worth remembering: EP06's Episode Seed already has independent evidence its split/title *is* settled (its own "Working title" line: "decided 2026-08-06 by Kevin/Hope") so that's cited directly; EP07's title was only ever "proposed... still to confirm in Content Brief" with no equivalent confirmation elsewhere in the doc, so its line explicitly says that part is still open rather than assuming Content Brief approval silently covered it too. Don't conflate "the two-part gate had one part resolved" with "the whole line is now approved" — check each half's actual evidence separately.

**Fix 2 — stale QA-report episode-number labels.** Checked every episode's `qa/` folder (only EP04, EP05, EP08 have one so far — EP06/EP07 have no transcript/QA yet). EP04/EP05 were clean (never renumbered). `EP08_AI_Will_Take_These_Jobs_First/qa/EP08_Anti_Slop_Report.md`'s heading still read `EP07_Where_Did_The_First_Jobs_Go.docx.md` — a label previously flagged (2026-08-06) and deliberately left alone with a note explaining why ("renaming the heading without re-running the scanner would misrepresent what was actually reviewed"). On inspection that reasoning didn't actually hold: the label was already an inconsistent hybrid of two different renumbers (mixing the post-first-renumber "EP07" with the pre-retitle "Where_Did_The_First_Jobs_Go" name) that never matched any real filename at any point, and per `HANDOVER.md` no transcript *content* ever changed across either renumber — only names — so relabeling to the current filename (`EP08_AI_Will_Take_These_Jobs_First.docx.md`) doesn't misrepresent the scan; the structural finding (36:43 runtime) is the same finding either way. Fixed, with a note recording the correction and why it's safe. Also fixed the twin copy at `06_Tools/QA/slop_report.md` — confirmed via reading `06_Tools/QA/hope_in_ai_slop_check.py` that this file is literally the scanner's own `DEFAULT_REPORT_PATH`, overwritten on every un-targeted run, so it's not a preserved historical artifact either — same reasoning applies with even less risk.

**General lesson for future "is this a preserved historical record or just a stale label" calls:** don't take a prior note's "this is deliberately left alone" framing as settled without re-checking its own premise — the EP08 report's earlier note assumed the heading captured a real filename snapshot, but a quick check of the actual rename history (via `HANDOVER.md`'s "no content changed, only names" framing plus checking whether the named file had ever really existed) showed it didn't. Verify the premise, not just the conclusion, before deciding something is out of scope.
