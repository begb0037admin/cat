16 August 2026, aimm Ozone-12 MixCheck redesign implementation. Kevin's approval gate for any visual/UI change requires an actual rendered screenshot, not a prose description of colours/layout — confirmed as a standing requirement mid-session, not just a one-off ask. This repo (and Windows machine) has no Playwright/Puppeteer installed, but both Chrome and Edge are present at their normal install paths (`C:\Program Files\Google\Chrome\Application\chrome.exe`, `C:\Program Files\Microsoft\Edge\Application\msedge.exe`) — no npm install needed, `chrome.exe --headless=new --screenshot=<out.png> <url>` is enough.

**Working recipe, in order:**
1. Fetch/edit the target HTML in a local scratch copy (never assume a local checkout is current — pull fresh via `gh api ... --Accept raw`).
2. Convert the Git-Bash `pwd` (POSIX-style `/c/Users/...`) to a real Windows path before building a `file://` URL: `WIN_DIR_URL=$(cygpath -w "$(pwd)" | tr '\\' '/')`, then `file:///$WIN_DIR_URL/yourfile.html`. A bare Git-Bash path (`file:///c/Users/...`, no drive-letter colon) gives Chrome on Windows a silent `ERR_FILE_NOT_FOUND` — both the "before" and "after" screenshot come back byte-identical (both the generic error page) with no other symptom, which is the tell.
3. Pass `--disable-gpu --no-sandbox --hide-scrollbars --window-size=<W>,<H>` and write the screenshot to an **absolute** path (a bare relative filename fails with "Access is denied").
4. If the page needs a specific tab/panel active by default (e.g. a single-page app that defaults to a different tab than the one being reviewed), flip the `active` class in a **throwaway copy** of the HTML before rendering — don't touch the real working copy just to stage a screenshot.
5. If you need to inject sample data to demonstrate a populated/non-empty state (worth doing — an empty-state screenshot hides most of a redesign's visible differences, e.g. status chips/progress-bar colours/highlighted pills only appear once data exists): don't call the app's own internal functions from an injected `<script>` unless you've confirmed they're on `window` — large single-file apps often wrap their logic in an IIFE, so `refPopulate is not defined` (or equivalent) is a likely first result. Set the DOM directly instead (`textContent`, `style.width`, `className`) by reverse-engineering the same values the real function would have produced from known sample inputs.
6. Run the network-dependent parts of the page (CDN scripts, font imports, API health checks) with `--host-resolver-rules="MAP * 0.0.0.0"` so blocked external domains fail instantly instead of hanging on DNS for the length of `--virtual-time-budget` — without this, `window.load` may never fire inside the budget and an injected `load`-listener script silently never runs (with no error, since nothing actually failed — it just never got the chance to start).
7. Prefer running your injected verification/sample-data script as an **immediately-invoked function at the point it appears in the document**, not registered on `DOMContentLoaded`/`load` — if the script is placed right before `</body>`, the entire document (including all the elements it needs) is already parsed by the time it runs, so there's no event to wait for, and it sidesteps gotcha #6 entirely.
8. Add a global `window.onerror` handler (appended right after `<head>`, so it's the very first thing that runs) that paints a fixed red `<div>` with the error message — this is what actually surfaced the two real bugs below. A silently-swallowed error in an injected `<script>` looks identical to "nothing happened" in the rendered screenshot; you cannot tell the difference without an on-page error surface (headless `--screenshot` mode doesn't show devtools console output anywhere you can see).

**Two real bugs this surfaced, both worth checking for on any future attempt:**
- **Nested same-quote escaping through a `bash heredoc → python triple-quoted string → JS string` chain silently drops a backslash.** Writing `\\'SF Mono\\'` (intending an escaped `\'` inside an already single-quoted JS string) inside a `python3 - << 'PYEOF'` heredoc came out on disk as a bare `'` with no backslash — a real `Uncaught SyntaxError: Unexpected identifier` that produced a completely unchanged screenshot with no other symptom (byte-size identical across multiple different edit attempts was the actual tell that something upstream was broken, before the `window.onerror` handler confirmed it directly). Fix: avoid nesting the same quote character across that many escaping layers — switch the outer JS string to double quotes (`"<span style=\\"...'SF Mono'...\\">"`) so no character needs double-escaping at all.
- Confirmed again: `.symptom.active`/`.fail`/`.warn` (2-class modifier selectors, specificity 0-2-0) get silently outranked by a new `#eq .symptom-grid .symptom` base rule (1-id + 2-class, specificity 1-2-0) regardless of source order, because ID beats class count. Any time a redesign pass adds an `#id`-scoped override for a class that also has un-scoped modifier states elsewhere in the same stylesheet, restate those modifiers under the same `#id` scope too, or the modifier's visual feedback silently disappears with no console error at all (pure CSS, nothing to catch).

Companion fact for future agents doing this: Kevin (per this session, generalised into a standing cross-cutting expectation) does not accept a written colour/layout description as the basis for approving a UI change — this whole recipe exists because that got explicitly rejected mid-session and the actual screenshot was then required before the "ready for review" report was accepted.
