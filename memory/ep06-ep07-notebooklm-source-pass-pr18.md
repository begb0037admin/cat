**The Philippines/Claim 027 gap, finally closed:** `memory/ep06-ledger-show-fit-field.md` flagged (2026-08-06) that Kevin's brief referenced a Philippines/Remotasks/Scale AI labor claim "already in the ledger" that didn't actually exist — only Kenya (then Claim 002) did. This task's brief explicitly named this as the priority item to check. Equal Times' "The Filipino workers at the sharp end of artificial intelligence" (Théophile Simon/HesaMag, 2026-04-24) independently verified and logged as EP07 Claim 018, with Claim 014's (Kwet) Show fit note updated in place to point to it instead of flagging the gap as open. This is the kind of thing worth checking `agent-commons`/this repo's memory for before assuming a brief's factual premise ("X is already sourced") is correct — it wasn't, the first time, and the brief this time explicitly asked to verify rather than assume.

**Duplicate-paper catch:** the pasted list included both an arXiv preprint link and an AAAI/IASEAI conference-proceedings link for "How Sovereign Is Sovereign Compute?" — same authors, same title, two publication stages of one paper. Fetching both independently confirmed this before logging; recorded as one claim (EP06 Claim 029) with both URLs, not two separate claims. Worth checking author/title match across superficially-different URLs before assuming a source list's items are all distinct.

**Mislabeled-source catch:** a source labeled "U Texas School of Law (Committee Statement)" in the pasted list, pointing to a `homeland.house.gov` PDF, turned out on fetch to be TeleGeography's own written testimony (Tim Stronge) to a US House Homeland Security subcommittee — nothing to do with UT Austin's law school. Logged under the correct attribution (EP06 Claim 025) with the mislabeling noted explicitly in the claim's own caveat, per this task's standing instruction not to trust a source's stated categorization at face value.

**Judgment calls, explicit not silent:** skipped Jacobin and Transform Review after fetching both and finding they're the same Varoufakis essay (already covered by the existing Claim 012 Technofeudalism sourcing, and too far into internal Marxist-debate weeds for the show's accessibility filter) — easy to conflate with logging MR Online's separate, older Kwet companion piece, so the PR body calls this out explicitly. Also skipped OpenEdition's "Faces at Stakes" (real, but about facial-recognition governance specifically, not AI-company sovereignty — too tangential), IJRISS (redundant with Featured claims already in the ledger), ThaiJO (same operational-not-sovereignty category problem already flagged for the existing Belfer FLEX/SMART entry), SPAR Project (an open fellowship-project *listing*, not a completed piece with findings — nothing to cite yet), and Temple iLIT (real, but its content is already better-sourced by three other newly-added claims). Included both UVA NSDPI and the Seattle University Law Review piece from the "your own judgment" list, each with an explicit one-line reason in the PR body rather than a bare "included."

**WebFetch-blocker fallback, confirmed a second method:** `html.duckduckgo.com/html/?q=...` (the established fallback per `memory/ep06-ledger-024-033-empire-corroboration.md`) itself got CAPTCHA-blocked partway through this pass. `https://r.jina.ai/<full URL>` (a text-extraction proxy — prepend it to any URL) successfully recovered readable text for several sources that failed both direct WebFetch and DuckDuckGo-HTML: DergiPark's PDF-download-link article, Mashable (blocked the direct fetch tool outright), and a Seattle University Law Review search. Two PDFs (Atlantic Council's report, the Columbia SIPA capstone) still failed even via r.jina.ai — the tool couldn't parse PDF binary either way; bibliographic details were confirmed via search instead, and the claims' own caveats flag that full-text figures/quotes weren't independently confirmed. Worth trying `r.jina.ai/<url>` as a second-tier fallback, after direct WebFetch and before concluding a source is unverifiable.

**Method — same Contents API PUT pattern, not the Git Data API tree method:** two files, no renames, no cross-file dependency in the same commit (unlike PR #17's two-file move) — created the branch via `git/refs` POST off `main`'s current SHA, then two independent Contents API PUT calls (`-F content=@file.b64 -f encoding=base64`, confirming again that `-f content=@file` silently sends the literal string while `-F` reads the file — same gotcha as `memory/ep07-to-ep06-175b-10t-refile.md`). Confirms `memory/status-handover-pr14-15-staleness-fix.md`'s note that Contents API PUT is the right default for straightforward multi-file-but-independent text edits, reserving the tree-rebuild method for renames or edits that must land in one atomic commit across files.
