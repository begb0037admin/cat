Title: Windows D:\ home migration — Codex-scarcity fallback triggered mid-task; robocopy from Git Bash needs MSYS_NO_PATHCONV=1
Date: 2026-09-23
Confirmed via: Live task on `begb0037admin/ai-news-channel` (PR #34, branch `cat/windows-dhome-migration-phase1`). Dispatched Codex via agent-commons failover wrapper (`node bin/codex-failover.mjs exec -s danger-full-access --skip-git-repo-check -`, prompt piped via stdin) for repo copy (robocopy C:->D:) + full path-repoint (10 repo files, .codex config.toml, Claude Code project memory, 19 shortcuts). Both accounts (`default`, `lelittecom`) hit quota mid-task; wrapper logged "All available accounts are exhausted or unavailable" right after a genuine, coherent completion report — the work itself had finished successfully (exit code 0) before quota bit, so a trailing exhaustion message doesn't necessarily mean the run's own output is bad, but no further Codex dispatches were possible afterward.
Fix / pattern: (1) `codex exec -s workspace-write` reliably crashes 0xC0000142 on this exact desktop (DESKTOP-MJDJM64) — go straight to `-s danger-full-access` with an explicit hard-scoped prompt and independent post-hoc verification (git diff/status, file hash comparison, live Test-Path on shortcuts) rather than trusting sandbox containment or Codex's self-report. (2) `< /dev/null` and piping a prompt via `| ... exec -` are mutually exclusive — don't combine them; the wrapper already safely ignores stdin unless a lone `-` arg is given, so `< /dev/null` is only needed when NOT using the `-` stdin form. (3) `robocopy.exe` invoked from Git Bash mangles single-dash flags like `/E` into a spurious "E:/" path argument (MSYS path conversion) — prefix the call with `MSYS_NO_PATHCONV=1` to fix. (4) Per `operating-model/COORDINATOR_AND_CODEX_POLICY.md` §5, when Codex is confirmed exhausted mid-task, Claude becomes the default fallback implementer for the *remaining low-risk, mechanical, easily-reversible* work (here: plain robocopy consolidation of stray folders, verified byte/count after) while still declining higher-risk/judgment work (live app config edits, deletions, final merge) that the original plan had reserved for a Codex-reviewed pass — record the gap explicitly in the target repo's HANDOVER.md rather than silently completing everything solo or silently stalling.
